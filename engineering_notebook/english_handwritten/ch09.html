Chapter 9: Fourth-Generation Programming

As our understanding of VEX IQ deepened, we realized that mechanical iterations alone couldn't meet our performance goals. To achieve more stable and efficient control, we launched a complete overhaul of the robot's coding architecture.

This chapter details how we applied software engineering principles to refactor our modular code, resulting in a massive performance leap.

Core Mission: Establish a clear, scalable, and fault-tolerant programming framework to support complex autonomous logic and tactical execution.

9.1 System Initialization

A reliable system starts with a precise initialization. We defined three core steps to ensure the robot starts in an optimal state.

1. Device Init

Set all motor torque to 100% and brake modes to "Hold" to resist external forces. Initialize all pneumatic subsystems simultaneously.

9.1 System Initialization (Cont'd)

2. Lift Reset

The program drives the lift arm downward until speed drops below 30%, signaling it has hit the physical limit. The encoder is then zeroed.

3. Pin Reset

Similar to the lift, the flip mechanism (fanzhuan) moves down until speed is below 10%, zeroes the encoder, and raises 10 degrees for readiness.

9.2 Telemetry & Driving

Efficient debugging and precise control are match-winners. We designed a real-time telemetry UI and a drive system with safety locks.

1. Screen Telemetry

The Brain screen displays key variables like "Beam" state, lift angle, and flip angle in real-time, allowing for rapid field diagnostics.

9.2 Telemetry & Driving (Cont'd)

2. Drive Control & Safety Lock

We introduced a "Safety Lock" mechanism where the robot only responds to sticks when the `dipan` variable is set to 1. A deadzone of < 20% was added to prevent stick drift.

The core purpose is to prevent accidental stick movement from interrupting precise automated sequences like grabbing or lifting. This ensures the integrity of the automation flow during the most intense match moments.

9.3 Button Logic Mapping (1)

Every controller button has a clear, intuitive function, with complex logic encapsulated into simple presses.

D, R3, L-Up

  • D: Hang 121 base (Pin=8)
  • R3: Lower 121 base (Pin=9)
  • L-Up: Cycle Beam state (1->2->3)

9.3 Button Logic Mapping (2)

E-Up, R-Down

  • E-Up: Open hook (Beam=0)
  • R-Down: Toggle Tower heights (Pin 0/1)

9.3 Button Logic Mapping (3)

F-Buttons

  • F-Down: Triangle heights (Pin 2/3)
  • F-Up: Manual grip (Jia +/- 1)

9.3 Button Logic Mapping (4)

E-Down

9.4 Automated Lift Sequences (1)

Automation is our scoring multiplier. We broke down complex workflows into states controlled precisely by code.

1. Start & Grip Sequence

We designed an auto-reset and one-key grip. When `Beam=0`, the system holds at a 40° prep angle. When `Beam=1`, the robot automatically backs up, lowers, grips, and lifts, then returns drive control to the operator.

9.4 Automated Lift Sequences (2)

2. Lift Heights

A State Machine manages height presets. `Beam=2` targets the 91 height; `Beam=3` targets 121. This ensures the lift arm moves reliably to exact positions, greatly boosting scoring speed and accuracy across different field elements.

9.4 Automated Lift Sequences (3)

3. Release Sequence

Pressing L-Down triggers a logic branch based on current Beam state. For instance, at 91 height, it lowers to 265°, releases the claw, raises to 350°, and resets.
